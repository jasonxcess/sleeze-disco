# Sleeze Disco (index-touch.html) — Playtest notes, Nov 12, 2026
Code-read playtest (no device run). JS syntax clean.

## Blockers
1. Sprites load from ./assets/*_sprite.png — file alone shows placeholder cards. Need to bundle assets folder or inline as data URIs.
2. Enemy telegraph is dead code: draw checks e.state === 'telegraph'/'charge' but enemies never get a state. No red warning; "Dash through red attacks" has nothing to read. Enemies show punch lunge the whole 0.75s windup.
3. Parry/dodge spam: no cooldown beyond active time (0.38s / 0.32s), not beat-judged. Parry = +200 pts +25 meter, best strategy by far.
4. Off-beat hits do full damage (1.0x), no MISS. Rhythm barely matters.
5. No audio latency compensation (AC.outputLatency/baseLatency) — on Android/Bluetooth ±65ms PERFECT is near impossible. Add calibration offset.

## Touch / phone
6. No ontouchcancel on D-pad → movement can stick (notification, palm). Use pointer events + pointercancel/pointerleave.
7. Facing only changes on movement — enemies behind you need a turn tap. Auto-face nearest on attack.
8. Portrait on Flip: 960x544 canvas ~1/3 screen. Add landscape prompt / overlay pad on canvas.
9. No diagonal on D-pad.

## Balance / feel
10. Enemies stack on the same spot (no separation), gang attacks.
11. Throw hits and takedown give no score/combo/meter; KOs give no bonus or KO float.
12. Endless: same wave and 120 BPM forever, no HP refill or ramp.
13. Boss Vex = big Bouncer, same AI.
14. Story clear has no Next Chapter button.
15. Desktop: keys stick on window blur (no blur reset).

## Good
Beat-reactive stage, lookahead audio scheduler, hit-stop/shake on PERFECT, float stacking, health-bar lanes, localStorage high score.

## Target is PS Vita (said Nov 12, 2026) — Vita PCH-2000, 3.65 HENkaku Enso
- Vita browser = JS 1.7/ES3-5, no Web Audio, canvas 2D only; only D-pad fires key events (face/shoulder buttons don't reach JS).
- This build won't parse there (const/let, arrows, template literals); no Web Audio = no music and judge() always HIT.
- Real route: native VPK (LÖVE Potion/Lua, or vitaSDK C + vita2d/raylib). Gameplay notes 2-4, 7, 10-14 still apply; touch notes 6, 8, 9 moot on Vita (phone-test only); latency note 5 mostly moot on native audio.

A real bug found by the probes: the queue first fired on the calMs-shifted clock, so every queued swing landed calMs late (33-47ms in headless, tens of ms on Bluetooth audio). Fixed: fireAt is an audio-clock time, so fireQueuedAction and nextBeatTimeFromNow compare the unshifted AC.currentTime. The queue fires on a 5ms timer (audio clock, not render clock) with the update() call as backstop. Probes after the fix: off-beat press fires 0-14ms from the beat, judged HIT, combo builds, no MISS float anywhere on an attack.
4. Parry edge-case decision (documented in code + here): parry and dodge are NOT queued. A parry is a reaction to a telegraph that can end before the next beat, so it fires the instant it is pressed, judged off-beat if the press is off-beat, and the counter check runs at press time while the prompt is up. Waiting would make the COUNTER prompt unanswerable and the strike-time parry fallback useless. Dodge follows the same rule: a dash that waits for the beat cannot dodge a strike landing in 0.25s. The queue covers punch/kick/throw only.
